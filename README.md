# ORCA第二代毫米波雷达SDK使用指南

1. python需要3.8及以上版本；
2. 对雷达网络配置的修改请见文档：《雷达设置网络配置操作指南.docx》
3. 对雷达SDK的配置请修改config.py文件，修改项具体含义请见对应注释；
4. 对雷达网络端口、雷达配置文件名称等进行修改后，请更新globalvar.py文件。

## 网页点云播放器

使用项目虚拟环境启动（无需前端构建工具）：

```bash
python3 -m venv .venv
env -u PYTHONPATH .venv/bin/python -m pip install -r requirements.txt
./run_player.sh
```

浏览器会打开 `http://127.0.0.1:8765`。从下拉列表选择 `data/` 内的日志，
或点击「打开本地文件」选择其他位置的 `.txt`、`.jsonl`、`.ndjson` 文件。
本地文件只在内存中解析，不另存副本；页面无需联网。加载后点击「播放」。

已安装依赖时直接运行 `./run_player.sh`；该脚本使用 `.venv` 并隔离 ROS 等环境的
`PYTHONPATH`。也可先 `source .venv/bin/activate`，再执行 `python replay_pointcloud.py`。
依赖包含 NumPy、scikit-learn（算法聚类）及 Matplotlib（原例程绘图）。

网页「ORCA 雷达滤波」勾选「启用算法滤波」后，调用 `radar_process.py` 的
`radar_filter`：固定杂波 → 直通 → RCS 指标 → 可选体素 → 可选 DBSCAN，
再执行速度/SNR/Noise 区间筛选。回放、实时和暂停帧都支持，参数修改即时重算。
提供全部算法参数和恢复默认按钮，默认关闭算法以便对比。RCS 指标不是标定后的绝对 RCS。
波形最大速度须根据 CFG 设置（默认沿用算法的 15.365 m/s，100m 配置约为 23.6 m/s）。
网页 dB 数据在调用原算法前还原为 0.1 dB 原始值，输出再转回 dB，保持原 RCS 阈值含义。
原模块未改写，聚类标签保留为返回数组第七列；当前绘图按径向速度绝对值阈值显示红色或绿色。
后台只处理当前显示帧，算法启用期间可能因聚类耗时跳过部分显示帧；原始接收与日志保存不受筛选影响。

- 播放 / 暂停：按钮或空格键；左右方向键逐帧查看。
- 点击或拖动进度条跳转；暂停时跳转仍保持暂停。
- 支持 0.25× 到 8× 倍速、循环播放，按日志的实际时间戳计时。
- 拖动三维点云旋转，滚轮缩放，「重置视角」恢复；点颜色按径向速度绝对值 |v| 着色：大于阈值为红色，否则为绿色（等于阈值也为绿色）。
  网页可调整着色阈值，默认 1 m/s；暂停时也立即生效，切换文件保留阈值。
- 速度、SNR、Noise 各有双端区间条，可拖动上下限或直接输入数值，播放和暂停时都即时生效。
  三个条件同时满足才显示，边界值包含在内；速度使用径向速度绝对值 |v|（m/s），正负速度按相同大小筛选；这不是三维合速度，
  SNR、Noise 按 TI 有符号 int16 原始值除以 10 换算为 dB，筛选步长为 0.1 dB。
  例如旧版原始阈值 513 现在对应 51.3 dB；Noise 不表示绝对功率 dBm。
  范围根据当前文件生成，切换文件或「重置筛选」恢复全范围。
  点数显示为「显示点数 / 原始点数」，显示点数也受坐标轴范围限制。
- 显示当前帧、目标点数、回放时间和原始接收时间。切换文件后停在首帧。

也可指定初始文件和选项：

```bash
python3 replay_pointcloud.py data/录制文件.txt --speed 2 --loop
python3 replay_pointcloud.py --data-dir /path/to/logs --port 8888 --no-browser
python3 replay_pointcloud.py --max-frames 1000 --limits -100 100 0 600 -30 30
```

原有 `--speed`、`--loop`、`--max-frames`、`--limits` 参数继续可用。
文件需为 SDK 保存的逐行 JSON 格式（`t` 为时间戳、`data` 为十六进制雷达帧）；
时间戳必须不递减。每个文件最多 128 MiB，数据一次性载入内存，大日志可先拆分，
或使用 `--max-frames` 限制解析帧数。服务仅监听本机，终端按 Ctrl+C 关闭。

验证播放器：

```bash
env -u PYTHONPATH .venv/bin/python -m unittest discover -s tests
node --test tests/playback.test.js
```

## 网页实时雷达

运行 `python3 replay_pointcloud.py`，在网页顶部点击「开始接收」。Python 监听
`globalvar.py` 中的 `DATA_PORT`（默认 UDP 52001），只接收 `config.py` 的
`radar_ip` 列表内的雷达。可通过 `--data-port 52001` 覆盖接收端口。
雷达需要把数据发往运行播放器的电脑，电脑网卡地址与雷达网络配置应匹配。
浏览器通过本地 HTTP 服务获取最新帧，无需浏览器直接访问 UDP。

- 雷达已在发送数据：直接开始接收即可。
- 需要像 `main.py` 一样配置并启动雷达：勾选「下发 CFG 配置」后开始接收。
  「配置文件」可选择项目 `cfg/` 下的 100m、300m、600m、1000m 等 `.cfg` 文件，
  或保留「按 config.py 分配」，使用 `radar_cfg_path` 为各雷达分配的文件。
  选择具体文件时，对 `radar_ip` 中所有雷达下发同一份配置（雷达下拉框仅控制查看画面）。
  网页列出目标 IP、文件路径及本次下发状态；选择文件本身不触发发送。
  新增自定义 `.cfg` 到 `cfg/` 后点击「刷新配置列表」即可选择。
  接收期间锁定选择，需要更换配置时先停止接收，再选择文件并开始接收。
  未勾选「下发 CFG 配置」时只接收，保留设备当前配置。
  下发整份 CFG，包含文件内的 `sensorStop`、`sensorStart` 等命令，
  自动跳过 `%`、`//` 行注释和 `/* … */` 块注释（包括 ORCA 100m 文件头）。
  未闭合的块注释会在下发前报错；真正的 CLI 命令被拒绝时仍停止下发并显示原因。
  向各雷达的 UDP 52000（`CFG_PORT`）发送配置；
  每条命令等待回复，2 秒超时后报告错误。先绑定接收端口，再下发配置。
- 默认勾选「保存原始日志」：保存到 `config.py` 的 `save_file_path` 下的新会话目录，
  每个雷达单独存储，每 5 分钟切换文件，格式兼容回放播放器。
- 雷达下拉框切换当前查看的设备，后台同时接收所有已配置雷达。
- 暂停只冻结画面，接收和保存继续；恢复跳到最新帧。实时模式禁用进度、逐帧和倍速，
  页面约每 100 ms 获取一次最新帧，完整接收帧保存在日志中。
- 速度、SNR、Noise 筛选同样可用；实时筛选范围随新数据向外扩展，已收窄的边界保留。
  实时坐标轴使用 `max_range`，也可用 `--limits` 固定。
- 选择文件可切回回放，后台接收仍继续；「查看实时画面」返回实时模式。
  「停止接收」释放端口、关闭日志，不向雷达发送 `sensorStop`；关闭网页不会停止后台接收，
  退出 Python 服务会停止接收。

请勿同时运行 `main.py` 的接收器，两者都需要独占同一个 UDP 数据端口。
端口占用、配置下发失败、接收中断和日志写入失败都会在网页显示。

## Z 坐标数据位置

现有日志的点云 TLV 从帧内 **第 48 字节偏移**开始（从 0 计数），
每点为 16 字节的 `x, y, z, v` 四个 float32。第 `i` 个点的 Z 来自
`data[56 + 16*i : 60 + 16*i]`，首点即字节偏移 56–59；
对于日志十六进制字符串，首点为 `record["data"][112:120]`。
解析后点列顺序为 `(x, y, z, v, snr, noise)`，网页用第三列作为 Z（米）。
解码结果保留 float32，不再降为 float16；网页没有额外高度或安装角校正。
这是雷达坐标系中的 Z，是否等于离地高度取决于安装姿态和雷达坐标定义。

解析器支持 TI 40 字节帧头的浮点 Cartesian 点云格式，显式使用小端字节序。
按 `numTLVs` 遍历 TLV，通过类型 1 查找 `(x,y,z,v)` float32，通过类型 7
查找 `(snr,noise)` int16；支持 TLV 调换顺序或中间插入其他 TLV。
所以偏移 48 和 56 仅适用于点云 TLV 在首位的日志，并非所有帧的固定位置。
TLV 长度不包含 8 字节 TLV 头；未知 TLV 和包尾填充跳过，长度、点数不一致、重复或缺失
必要 TLV 的非空帧报错；合法零目标帧返回空点云。实时接收跳过坏帧，回放报告错误行号。
不自动兼容其他帧头长度、压缩点云或不带 side-info 的格式，避免误解数据。
原始十六进制日志不变，重新加载后显示修正后的精度及 dB 数值。


| 参数 | 第一行 | 第二行 | 含义 |
|---|---:|---:|---|
| 子帧 | -1 | -1 | 应用于所有子帧 |
| 处理方向 | **1** | **0** | 1＝多普勒方向，0＝距离方向 |
| CFAR 算法 | 3 | 3 | OS-CFAR，有序统计方法 |
| 窗口长度 | 16 | 16 | 单侧噪声参考窗口长度 |
| 保护长度 | 0 | 0 | 此版本 OS-CFAR 要求为 0 |
| 噪声移位 | 0 | 0 | 噪声累加值的移位除数配置 |
| 循环模式 | 1 | 1 | 启用循环边界处理 |
| 检测门限 | **20.0 dB** | **15.0 dB** | 相对于估计背景的检测门限 |
| 峰值聚合 | 0 | 0 | 禁用 |
| OS-K 参数 | 7 | 7 | OS-CFAR 的 K 值配置 |
| 边缘 K 缩放开关 | 0 | 0 | 禁用 |
| CFAR 启用 | **1** | **0** | 第一行启用，第二行禁用 |
